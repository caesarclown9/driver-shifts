# Дневник смен водителя

Сервер (FastAPI + SQLite) отдаёт поездки и сводку за день, клиент (React) показывает день, переключает дни и добавляет поездку.

## Запуск

Нужны Python 3.12+ с [uv](https://docs.astral.sh/uv/) и Node 20+ с pnpm.

```bash
# терминал 1 — API на :8000, при старте загружает data/trips.json
cd backend && uv run uvicorn --factory app.main:create_app --port 8000

# терминал 2 — клиент на :5173, /api проксируется на :8000
cd web && pnpm install && pnpm dev
```

Открыть http://localhost:5173. Документация API — http://localhost:8000/docs.

Тесты: `cd backend && uv run pytest`.

## Данные

`data/trips.json` — неделя смен 28.09–04.10.2026 (01.10 — выходной, поездок нет), генерируется детерминированно `scripts/make_seed.py`:

```json
{
  "trips": [
    {
      "id": "8f1d2368-c870-42e9-b277-db7e8283ddd9",
      "started_at": "2026-09-28T08:05:00+06:00",
      "ended_at": "2026-09-28T08:31:00+06:00",
      "amount": "510.00",
      "payment": "cash",
      "commission": "76.50"
    }
  ]
}
```

- Время — ISO 8601 **с часовым поясом**, время без пояса отклоняется.
- Деньги — **строкой** с не более чем двумя знаками после точки. Числа (`510.5`) отклоняются, чтобы float не попал в расчёт.
- `payment` — `cash` или `card`; `commission` — сумма в сомах (не процент), от 0 до суммы поездки.
- Файл грузится при каждом старте через ту же проверку, что и API; уже загруженные поездки пропускаются. Одна битая поездка останавливает загрузку с указанием её номера — тихо пропустить её значило бы тихо исказить итоги дня.

Настройки через окружение: `DS_DB_PATH` (по умолчанию `backend/var/trips.db`), `DS_SEED_PATH` (пусто — не загружать), `DS_TIMEZONE` (`Asia/Bishkek`), `DS_CURRENCY` (`KGS`).

## API

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/days` | дни, в которых есть поездки, с их числом |
| GET | `/api/days/{YYYY-MM-DD}` | сводка дня + поездки по времени начала |
| POST | `/api/trips` | `201` создана · `200` уже была (дубль не создан) · `409` тот же `id` с другими данными · `422` ошибка в поле |

Сводка: `trips`, `revenue` (выручка), `commission`, `net` («на руки» = выручка − комиссия), `cash` и `card` — число поездок и выручка по каждому способу оплаты.

## Решения

**День поездки** — день её начала по времени водителя (`Asia/Bishkek`). Поездка 23:50–00:20 входит в день, когда началась. Поэтому в данных 05.10 есть три поездки — хвост ночной смены 04.10 после полуночи.

**Деньги.** Decimal в коде, строки в JSON, целые тыйыны в SQLite. Сводка только складывает и вычитает суммы с двумя знаками, поэтому округления нет нигде — и нет правила округления, которое могло бы разойтись между сервером и клиентом. Клиент форматирует строку из API, не превращая её в число.

**Защита от дублей**, два уровня:
1. `id` поездки (UUID) генерирует клиент один раз на ввод. Повтор после таймаута уходит с тем же `id` → `200` и сохранённая поездка. Тот же `id` с другими данными → `409`, исходная поездка не меняется. Без `id` сервер выводит его из содержимого поездки — слепой повтор тоже не создаст дубль.
2. Одна и та же поездка (начало, конец, сумма, оплата, комиссия) под **другим** `id` — тоже дубль: уникальный индекс в БД. Время сравнивается как момент, а не как строка: `10:00+06:00` и `04:00Z` — одна поездка.

Проверка и вставка идут в одной транзакции `BEGIN IMMEDIATE`, поэтому два одновременных запроса не проходят проверку оба. Тесты гоняют 16 параллельных отправок; если убрать блокировку или проверку по содержимому, падают именно они.

**Проверки ввода:** сумма > 0 и ≤ 1 000 000; комиссия 0…сумма; окончание позже начала и поездка не длиннее суток; оплата из `cash`/`card`; лишние поля отклоняются. Ошибка `422` указывает поле, клиент показывает её под этим полем.

## Что не сделано

- Нет авторизации и нескольких водителей — один дневник на один сервер.
- Нет редактирования и удаления поездок.
- Пересечение поездок по времени не проверяется (в задании не требуется; у водителя с подсадками оно бывает законным).
